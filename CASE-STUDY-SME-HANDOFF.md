## How the conversation works

- Work from the evidence already available in the SME's environment.
- Prefill the source-package template instead of asking the user to complete a blank document.
- Try to answer each field from durable evidence first.
- Offer useful framing and media suggestions, clearly labeled as suggestions.
- Ask only questions the evidence cannot answer or that require the user's judgment.
- Ask one to three related questions at a time through native multiple-choice message polls when available.
- Put the recommended option first, explain each option's consequence briefly, and allow a free-form answer.
- Continue in rounds until the high-value gaps are resolved or explicitly left open.
- Return the completed, document-ready source package and a concise list of remaining open items.

## Visual output

- Identify the claim each proposed visual must communicate.
- Capture or locate clean screenshots, recordings, named key states, and source artifacts when the SME environment makes that practical.
- Record source paths, product version, permissions, timing, and missing variants.
- Suggest whether each claim needs product capture, an editorial evidence collage, a programmatic illustration, a carousel, or composition.
- Propose the smallest evidence-led set of core flows; the two rows in the Rem scaffold are an example, not a required count.
- Do not invent final page styling or a unique device/cursor treatment for the project.
- If an approved basic-compositor preset is available, the SME may use it to produce consistent device framing, cursor or tap cues, simple zoom, a poster, and a web video.
- Leave advanced 3D device and project-cover direction to the portfolio-level compositor workflow.

## Evidence rules

- Treat the current code, product artifacts, research, and source documents as primary evidence.
- Treat agent memory and conversation history as leads that must be verified.
- Do not invent metrics, research, decisions, team structure, chronology, or outcomes.
- Distinguish current product behavior from historical behavior and unfinished work.
- Prefer an explicit placeholder or question over unrelated supporting media.
- Do not edit the portfolio code unless Samuel explicitly asks you to implement it.
